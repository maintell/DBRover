# 07 · 信息架构（按功能分组，聚焦主要功能的决策）

## 1. 现状 IA（取证 `index.html:11-43`）
```
顶栏（单一平级层，~15 按钮）
 ├ 连接组：连接 / 新连接 / 刷新
 ├ 混合组：AI / 比对 / 体检(hidden) / 指标(hidden) / 会话(hidden)
 ├ 新建组：新建表 / 新建视图 / 新建序列(h) / 新建类型(h) / 新建例程(h)
 └ 尾组：设置 / 退出
标签栏 → 对象树 sidebar → 工作区（SQL + 工具条 + 结果）
```
问题：所有功能同一层级、永远可见；核心闭环没有被突出；次要/管理动作与主角抢视线；新能力只能继续加按钮（顶栏已 `overflow-x:auto`）。

## 2. 重设计 IA（三层：域 → 组 → 动作）
```
┌─ ContextHeader（常驻，轻量）：品牌 | 当前连接▾ | 环境/身份/配置徽标 | 设置 | 退出
├─ ActivityRail（左，一级功能带，≤5 项，渐进披露）
│    ● 数据        ← 默认 / 主角（data-domain="data"）
│    ○ 结构        → 二级：设计器 / 新建(表·视图·序列·类型·例程) / 比对
│    ○ 监控        → 二级：性能 / 会话 / 巡检
│    ○ AI          → 二级：会话 / 审批
│    ○ 运维任务    → 空状态（CLI/API 可用、界面未接入）
└─ DomainView（右，当前激活域的内容区）
     └ 数据域：对象面板 | [SQL 标签栏] | 编辑器+工具条 | 结果/数据编辑
       （结构/监控/AI 域复用其现有面板，进入时不重建 #sql/#results 节点身份）
```

## 3. 分组依据（证据）
- **数据**为主角：`docs/05` 14/15、`docs/06` 12/12 验收完成度最高，README 把它排在日常链路最前（`00 §5`）。
- **结构/比对/监控/AI 按任务进入**：完成度次之（`docs/07` 10/12、`docs/09` 8/12、M3 切片一、二），且非每次任务用。
- **运维任务如实标注**：界面零入口（`docs/12` §2.6），不伪装主角。
- **工具类收敛**：连接/设置/令牌/模式/退出是全局上下文或偶发操作，置于 ContextHeader 角落。

## 4. 「聚焦主要功能」的可验证规则
1. 默认激活域 = `data`；应用启动到「可写第一条 SQL」零导航点击。
2. 一级入口 ≤5；其余所有动作在二级，默认不可见（渐进披露）。
3. 顶栏按钮数从 ~15 降到 `≤4`（连接选择 + 设置 + 退出 + 环境徽标），且不随新功能增长。
4. 「新建序列/类型/例程」「体检/会话/指标」「比对」等不再常驻顶栏，进入对应域二级导航。
5. 域切换不清空 `state.current`、不重建 `#sql`/`#results` 节点身份（保 `ui2.js` 活 DOM 引用）。
6. 文案克制：一级导航用「数据/结构/监控/AI/运维任务」单词 + 图标 + `aria-label`，删掉 title 长标语；删完若看不懂，靠 `ContextHeader` 当前区标题与布局解决，不加回说明文字。

## 5. 与现有 id 的兼容
IA 是「容器与父子关系」的重排，**不是 id 改名**。所有按钮 id、抽屉 id、面板 id 保留原值并挂到新容器下；`app.js`/`ui2.js` 的 `$('id')`、`getElementById` 全部继续命中。逐项映射见 `18-migration-map.md`。

## 6. 响应式/可达性（ui-ux-pro-max）
- `ActivityRail` 桌面常驻；窄屏（`@media max-width:900px` 已有）折叠为可唤出抽屉（`@media` 段已存在，扩展而非重写）。
- 每个一级入口 `aria-label` + `aria-current` 表达激活态；Tab 顺序与视觉顺序一致，focus 可见（`quick-reference.md` §1）。
- 不依赖 hover 才能发现功能；点击目标 ≥44×44（`quick-reference.md` §2）。
