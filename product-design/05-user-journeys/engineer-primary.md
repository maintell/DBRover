# 旅程 · 工程师（主用户，日常查数改数）
- **为什么进系统**：追一个慢查询 / 加一个字段 / 修一批脏数据 / 摸清陌生库（docs/01 S1/S2/S3/S5）。
- **任务**：选连接 → 浏览对象 → 写跑 SQL → 看结果 → 改数据 → 提交。
- **成功标准**：结果正确、变更已持久化且可回滚、有明确成功反馈、下游（对象树/结构）读到新状态。
- **离开条件**：关闭标签/切换连接/退出；未提交 pending 有确认，不静默丢。
- **重设计收益**：打开即主流程（零导航点击）；功能按域收敛；文案靠布局看懂；data-domain/data-action 可脚本化。

# 旅程 · DBA（排障/变更）
- 进入：监控域（性能/会话/巡检）或结构域（设计器/比对）。
- 成功：定位问题（首屏结论）或完成带回滚的结构变更；Kill/不可逆均需确认并记审计。
- 离开：关面板即停采集；返回原域不丢连接。

# 旅程 · 只读用户
- 进入：数据域浏览/查询；所有写入口不可见且 service 双层拦截（row_actions_ui_test.go）。
- 成功：只看不改，看到「只读」环境/模式徽标（#env/#profile）。
- 离开：同上。

# 旅程 · AI Agent（一等公民）
- 进入：AI 域会话，工具与人工共用 service（docs/11 §1）。
- 成功：结论附真实执行过的 SQL 与结果摘要；写操作 100% 审批。
- 离开：会话结束；审批拒绝可恢复，不静默执行。
