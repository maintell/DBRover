# ADR-0012 · 迁移的约束与默认值：匿名唯一约束、只搬字面量默认值、注释不搬

- 状态：**已采纳（部分实现）**
- 日期：2026-11-05
- 影响面：`internal/service/migrate.go`（`BuildMigrationDDL` / `BuildMigrationNotes`）、`docs/08 §4`

---

## 背景

迁移目前只搬列定义 + 主键 + 普通索引。唯一约束、默认值、注释会**静默丢失**——
目标表看起来能查，但唯一性不再被强制、默认值没了、注释也没了。这三类都不能靠
「顺手拼一句 DDL」解决：

- 唯一约束在 PostgreSQL 里会建同名索引，跨表可能撞名；
- 默认值可能是表达式（`nextval(...)`、`CURRENT_TIMESTAMP`、`now()`），跨引擎不等价；
- 注释在三个引擎的写法与权限要求都不同。

## 决策

### 1. 唯一约束：写**匿名** `UNIQUE (cols)`，不写约束名

```sql
CREATE TABLE t (
  id integer NOT NULL,
  email varchar(64),
  PRIMARY KEY (id),
  UNIQUE (email)
)
```

理由：PG 的唯一约束会隐式建一个**与约束同名**的索引，而索引名在 schema 内必须唯一；
沿用源约束名在目标 schema 里可能撞名（尤其 `users_email_key` 这种通用名）。匿名约束
由引擎自己起名（`t_email_key`），冲突概率低且可预期。

前提：源表上本来就有这个唯一约束，所以源数据不可能有重复——**不需要**额外的查重
预检。若将来支持「源上没有、目标上加」的场景，必须先查重。

### 2. 默认值：只搬**字面量**，表达式一律不搬

判定复用现有的 `defaultPattern`（`NULL` / 布尔 / 数字 / 单引号字符串 / `CURRENT_TIMESTAMP`
等少数几个当前时间函数）。不在白名单里的一律跳过，并在 `BuildMigrationNotes` 里出声：
「列 x 的默认值未迁移（表达式不受支持）」

理由：

- `nextval(...)` 是序列引用，跨引擎（MySQL 的 `AUTO_INCREMENT`）语义不同；
- `now()` / `CURRENT_TIMESTAMP` 看似通用，但精度与时区行为不同；
- **宁可少搬并说出来，也不要搬一个行为不同的默认值**——后者会在用户不知情时
  改变写入数据的含义。

### 3. 注释：不搬，但要说出来

表注释与列注释都进 `BuildMigrationNotes`：「表/列注释未迁移」。三个引擎的写法不同
（MySQL 在 `COMMENT` 子句、PG 用 `COMMENT ON`、SQLite 没有），而注释不影响数据正确性，
放进 v1 只会增加失败点。

## 后果

**正面**

- 迁移后唯一性仍然被强制（这是数据正确性问题，不是装饰）。
- 字面量默认值能过去，表达式型的缺口被明确说出来。

**负面 / 必须说清**

- 匿名约束的名字与源不同：只影响「按名字找约束」的脚本，不影响约束本身。
- 表达式默认值要人工补，迁移报告里会列出来。
- 注释丢失。

## 验证计划

1. 源表带 `UNIQUE (email)`：DDL 里出现匿名 `UNIQUE ("email")`，且**不出现**源约束名。
2. 源列带字面量默认值（`'0'`、`0`）：DDL 里出现 `DEFAULT`。
3. 源列带表达式默认值（`nextval('s')`）：DDL 里不出现 `DEFAULT`，且 notes 里有该列。
4. 源列带注释：notes 里有「注释未迁移」。
