# ADR-0010 · 备份加密：口令每次从 stdin 读，PBKDF2 + AES-GCM

- 状态：**已采纳（已实现）**
- 日期：2026-11-05
- 影响面：`internal/service/backup*.go`、`cmd/dbrover`（`-passphrase-stdin`）、`docs/08`

---

## 背景

容器 flags 的 bit0 一直是「加密」保留位。实现前必须先答一个问题：**密钥从哪来？**

| 方案 | 问题 |
|---|---|
| 存 OS 凭据库（已有 `dbrover secret`） | 备份文件常被拷到别的机器/给别人；绑本机凭据库等于「换台机器就解不开」，而那正是备份要救的场景 |
| 命令行参数 | 进程列表与 shell 历史都能看到 |
| 环境变量 | 崩溃转储、子进程可见；且比命令行更难发现泄露 |
| **每次从 stdin 读** | 用户要自己保管口令；丢了就真的打不开 |

## 决策

**口令每次从 stdin 读（`-passphrase-stdin`），不落盘、不进凭据库。**

算法：`PBKDF2-HMAC-SHA256`（210000 次迭代，16 字节随机盐）派生 32 字节密钥 → `AES-256-GCM`，**每段一个随机 nonce**，nonce 前置在密文里。

- 只用标准库（`crypto/aes`、`crypto/cipher`、`crypto/pbkdf2`、`crypto/rand`），不引第三方加密库。
- 段内顺序：先 gzip（可选）再加密；读端反过来。
- **头部保持明文**：列出对象、显示引擎与时间、以及派生密钥必需的盐与迭代次数都要在明文里。加密只覆盖段。
- 读到未知 flags 位直接拒绝；加密位与压缩位可同时置位。

## 后果

**正面**

- 备份文件可以安全地放到别处：没有口令，段里的表名、列值都读不出来。
- AEAD 自带完整性校验：改一个字节，解密就会失败（不是静默解出乱码）。

**负面 / 必须说清**

- **口令丢了没有任何后门**。不做「恢复码」——那等于把密钥再存一份。
- **头是明文的**：别人能看到这个备份来自哪个引擎、有哪些表、什么时候备的。要连元数据都藏起来，得把整份文件（含头）再包一层加密，v1 不做。
- AEAD 无法区分「口令错」与「密文被改」，错误文案必须两者都提（`口令不对，或文件已被改动`），否则用户会以为文件坏了。

## 验证

- `TestBackupEncryptedRoundTrip`：加密 + 压缩的容器，文件里搜不到 `CREATE TABLE` 明文；正确口令能恢复出数据。
- `TestRestoreNeedsPassphrase`：没给口令 → `ErrBackupNeedPassphrase`。
- `TestRestoreWrongPassphrase`：口令错 → `ErrBackupBadPassphrase`，文案含「也可能被改动」。
- `inspect` 对加密容器仍能列出对象（头明文）。
